# T-08 · Tầng dữ liệu (interface + Local IndexedDB + seed)

## Mục tiêu
Cho phần còn lại của app đọc/ghi dữ liệu qua **một interface duy nhất**, và **chạy
ngay với dữ liệu demo** (IndexedDB) không cần backend. Sau này chỉ đổi env để dùng Supabase.

## Ngữ cảnh cần biết
- Kiến trúc §5.1: **DataRepository** interface, 2 hiện thực (Local/Supabase), chọn
  theo env. **UI chỉ gọi `getRepository()`** (CONVENTIONS §2).
- `snapshot(clanId)` là "trục chính": nạp cả dòng họ 1 lần để domain tính trong bộ nhớ.
- Local-first: dữ liệu ở **IndexedDB** (dùng `idb`), seed demo lần đầu.

## Phạm vi
**Trong:** `repository.ts` (interface + kiểu phụ), `local/db.ts` (mở IndexedDB qua
`idb`), `local/localRepository.ts` (CRUD members/parentLinks/unions/branches/clans +
`snapshot`), `local/seed.ts` (ghi `demoClan` lần đầu), `index.ts` (`getRepository()`
theo env: có `NEXT_PUBLIC_SUPABASE_URL` → để chỗ cho Supabase (T-17), else Local).

**Ngoài:** hiện thực Supabase (T-17); UI. Không gọi domain logic ở tầng data.

## Đầu vào đã có
- `T-02`: types + `ClanSnapshot` + `tests/fixtures/demoClan.ts` (nguồn seed).

## Việc phải làm
1. `repository.ts`: interface `DataRepository` gồm nhóm `clans/members/parentLinks/
   unions/branches/memberships/invites` (list/get/create/update/delete phù hợp) và
   **`snapshot(clanId): Promise<ClanSnapshot>`**. Kiểu `MemberFilter` cho tìm/lọc.
2. `local/db.ts`: mở DB `giaphaviet` với object stores tương ứng; version + upgrade.
3. `local/localRepository.ts`: hiện thực đầy đủ interface trên IndexedDB; `snapshot`
   gộp mọi store theo `clanId`.
4. `local/seed.ts`: nếu DB rỗng → ghi `demoClan`. Idempotent.
5. `index.ts`: `getRepository()` (singleton) chọn theo env; gọi seed cho Local.

## Quy ước bắt buộc
- Tầng data không import domain/UI (CONVENTIONS §2). Trả Promise. Không lẫn nghiệp vụ.
